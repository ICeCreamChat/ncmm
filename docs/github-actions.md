# 本 fork 的 GitHub 定时任务

日常无需手动操作。`Daily ncmm musician tasks` 每天计划在北京时间 07:17 运行；GitHub 可能延迟触发。

打开仓库的 **Actions → Daily ncmm musician tasks → 最近一次运行 → Summary**，可以查看运行前后的网易云任务进度。原始日志中还会分别记录近 30 天普通播放量和有效播放任务字段。

## 当前部署

- 使用上游发布镜像 `ghcr.io/3899/ncmm:1.2.5`，启用 `play.webSession`。
- 使用现有主账号与两个辅助账号的仓库 Secrets，无需重新登录或公开 Cookie。
- 目标歌曲是 `清泉不断流`（2721714728）和 `晚霞映小舟`（2721485994）。
- 每账号每日随机目标仍为 40～100，单次目标仍为 20～40；保留日推混听、完整时长等待、本人歌曲过滤与串行执行。
- 播放任务与笔记任务的服务端状态都为 `100` 后，保存现有的当月完成标记，当月后续定时运行停止请求账号。

## 进度为什么分开记录

新版任务的 `progressRate/totalCompleteNum` 与普通 `recentPlayCount30` 是不同字段。工作流直接查询任务接口，保留 `missionStatus`、进度字段、`taskProgressText` 和说明；不把普通播放量转换成有效播放任务进度，也不把 `4/100` 当作 4 次播放。

2026 年 10 月 8 日实际查询到网易云对这个任务的说明是：**“目标进度由播放量及播放人数达成情况共同决定”**。只有两个固定账号反复播放不会增加播放人数；增加上报次数不保证任务进度增长，程序升级也不能替代真实听众。

辅助账号的播放接口返回成功，只表示上报被接受。任务是否计入，以网易云返回的有效播放任务进度和完成状态为准。任务未完成时，工作流继续按原限额播放，避免普通播放量超过 650 后错误地停止。

## 手动查看或验证

在 **Run workflow** 中选择 `run_mode=status`，只查询任务进度，不签到、发笔记或播放。

只有需要手动运行任务时才选择 `run_mode=full`。`playback_max` 默认是 `0`，表示沿用原配置；填 `1` 可将这一次每个辅助账号的播放目标降为 1 首。它只降低单次目标，不提高配置中的限额。同一天额外运行前，需把当天已有运行的播放数量一起计入额度。

## 后续升级

定时任务的镜像版本在 `.github/workflows/run-ncmm.yml` 的 `NCMM_IMAGE` 中指定。更新 fork 源码或构建自己的镜像，不会自动改变这个版本。升级时先核对上游发布说明，再用小额运行验证配置兼容和网易云原始任务进度。

账号文件保持私有权限，容器以 GitHub runner 用户运行，避免新版升级配置后变成 root 所有而导致后续步骤无法写入。运行结束仍执行原有账号文件清理。

新版增加的默认示例歌单已在配置中清空，并在迁移后再次指定目标歌池，避免其他音乐人的作品占用本任务的播放额度；日推混听仍保留。
